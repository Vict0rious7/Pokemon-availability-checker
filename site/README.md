# Site

Static site: Vite + Preact + TypeScript. The engine (`../engine/src`) runs in the browser, in a Web Worker; the data files (`../data`) are bundled at build time.

    cd site
    npm ci
    npm run dev       # local server
    npm run build     # Finder table, shopping lists and their check, type check, production build in dist/
    npm run preview   # serve dist/

`npm run build` first runs `scripts/finder.ts`, which computes the Finder table with everything owned (about 3 s) into `src/generated/`. Then `npm run lists` writes the shopping lists for "What to get next" into `public/generated/lists.json` (about 4 min, 6 GB heap), and `npm run listcheck` checks them against the engine. Neither output is committed. `npm run dev` does not rebuild the lists: run `npm run lists` once first.

## How it works

- `src/state.ts`: the user's selections (`Profile`), their conversion to the engine's `Owned`, and the URL hash (`#g=…&hw=…&s=…&to=…&gen=…`), so a profile can be bookmarked and shared.
- `src/worker.ts`: runs the fixed point once per set of owned games and hardware (cached), then answers destination and scope from it. Changing only the destination or the generations takes milliseconds.
- `src/main.tsx`: inputs, results (grouped by generation; "move before 25 Feb 2027", missing, can reach, can't live there), credits. `src/finder.tsx`: the Finder. `src/path.ts`: turns a path's route ids into places.
- `src/labels.ts`: game names and URL codes, hardware, services, flags, HOME rewards and gifts, and the planner's item names.
- `src/plan.tsx` + `src/planner.ts`: "What to get next", in a second worker that loads the shopping lists on first use and runs `engine/src/optimise.ts`. The boxes (no GO, software already installed or modded) are not saved in the URL.
- `src/suggest.ts`: "Suggested for your games" above the consoles and services lists.
- `src/themes.ts` + `src/themes.css`: wallpapers, picked in the header ("Wallpaper") and remembered in the browser: a subtle pattern behind the whole page plus a touch of its colour on the result boxes. Forest (default), City, Desert, Savanna, Volcano, Snow, Cave, Seafloor, Sky, Plain. The patterns are original, slightly pixel-style drawings generated by `scripts/biomes.py` (edit there, then `python3 scripts/biomes.py src/themes.css`).

## Speed (measured 15 Oct 2026)

The fixed point dominates. Chromium, cloud machine about 2× slower than an M-series Mac: 7 games ≈ 0.45 s, every game once ≈ 4.8 s (Node), everything ×2 ≈ 5.4 s; with 4× CPU throttling (a mid-range phone) 1 s and 24 s. Hence the worker, the cache, and the bottom bar on phones. Engine speed-ups are a Phase 5 option if real users find it slow.

## Deploy

`.github/workflows/site.yml`: on every push to `main`, the Phase 1 and Phase 2 checks run, then the site is built (with the shopping lists and their check); a failing check stops the chain. The `deploy` job publishes from `main` only.
